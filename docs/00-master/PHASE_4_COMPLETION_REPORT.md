## 4. Database migrations

0003 adds model_versions, predictions, forecast_evaluations, risks and intelligence_outbox,
plus telemetry-time and prediction-scope indexes. Unique run keys, one open risk per scope,
evaluation-to-prediction references and JSON/state checks apply. Ordered versions 0/1/2 upgrade
to 3; unsupported versions fail closed. Before actual launch, the Phase 3 store was backed up.
Read-only comparison after actual migration found zero existing telemetry rows changed or lost.

## 5. API changes

GET /api/v1/intelligence returns quality/expiry-aware current intelligence, model metadata,
evaluation summary, recent risks and counts. GET /api/v1/forecasts?before=N exposes descending
prediction history (20/page). GET /api/v1/intelligence/events?after=N exposes ascending events
(20/page). Facility edits accept optional simulation_demand_threshold_kw. Native IPC adds only
intelligence_read for a fixed authenticated snapshot route. Generated contracts are updated.

## 6. Event changes

IntelligenceEvent v1: ForecastGenerated, ForecastFailed, ForecastEvaluated, RiskDetected,
RiskUpdated, RiskResolved, RiskSuperseded. Typed payloads, durable sequence, scope, UTC time,
model/evidence, actor and correlation/causation/idempotency IDs are retained. Prediction/risk
and outbox changes are atomic; evaluation/event changes are atomic. Replayed runs do not emit
duplicate events. Cloud upload and acknowledgements remain Phase 8.

## 10. Manual verification steps

Run npm run desktop:native; let normal simulator telemetry build five sufficiently complete
minute bins. Open Forecasting & Risk and inspect model, curve, coverage and source evidence.
In Facilities select the facility and set an illustrative simulation threshold. A threshold
below the forecast opens a risk. With a fixed suitable threshold, spike then normal exercises
updates and resolution; bad/stale/disconnected makes current assessment UNKNOWN without resolving
an open risk. Clearing/changing facility configuration supersedes it. Leave a full 30-minute
future window plus five seconds for prospective evaluation. Restart and inspect retained records.

## 12. Known limitations

Flat baseline only; 1 Hz active_power/kW; five past minute bins and 30-minute horizon. At least
48 distinct good seconds per enabled telemetry asset per minute are required. No calibrated
intervals/probabilities, billing-period demand model or site accuracy qualification. One local
facility, 1,440 prediction attempts and 10,000 intelligence events; capacity fails visibly without
discarding history. Previous telemetry/registry limits apply. UI shows latest prediction/recent
20 risks; full prediction/event history is available through scoped APIs. No dispatch capability.

## 13. Mocks still present

Factory signals and threshold experiments are explicitly simulated. UI unit tests mock native
IPC. Long evaluation tests use chronological normalized fixtures; a separate integration case
uses the real normalizer/ingestor and factory batches. Native validation uses the real runtime,
SQLite, simulator and bridge. No fabricated historical data or accuracy is inserted into the UI.

## 14. Technical debt introduced

Bounded JSON-backed local intelligence tables, row-digest provenance rather than signed audit,
full bounded evaluation scans for summary, and fixed baseline cadence. No central governance,
trained-model promotion, calibration, drift tracking, cloud ACK/compaction or operator risk
acknowledgement. Facility name/timezone edits conservatively supersede prior risk alongside
threshold changes. Overlapping evaluation windows are correlated. Existing packaging, durable
store ownership and user identity/RBAC debt remains; the QA bundle is not a distributable installer.

## 15. Security considerations

Scope remains server-owned. Private bearer authentication, Origin rejection, response/body limits
and fixed native routes remain. No token enters React or logs. Forecast/risk services do not call
machines, optimization or dispatch. The threshold is a user-configured simulation parameter, never
a real safety limit. operational_ready remains false. Audit actor denotes the inference worker,
not an authenticated human identity. Missing data never means CLEAR or resolved risk.

## 16. Performance considerations

Worker wakes every five seconds; unique minute/config/quality keys bound persisted runs. Source
queries use the time index and bounded store; bins use distinct-second buckets. One matured
forecast is evaluated per cycle. UI polls every two seconds without overlapping calls. Inference
uses a joined background thread; SQLite transactions serialize writers. No industrial-scale
throughput, long soak or accuracy claim is made. Capacity counts and failure states are visible.
