SIMULATION. Phase 4 forecasting/risk has not begun.

## 4. Migrations

Migration 0002 creates scoped registry and configuration_outbox tables/indexes. Versions 0/1
upgrade in order to 2; unsupported versions fail closed. Original identity, telemetry rows,
sequence, counters and telemetry outbox survive. Bootstrap imports the existing five simulation
assets and adds versioned seed configuration events exactly once. Before actual native launch,
a SQLite backup was taken. Comparing the upgraded workspace DB against that backup found zero
old telemetry rows missing or changed; current schema was 2.

## 5. API contracts

GET/POST /api/v1/registry and GET /api/v1/registry/events?after=N. Typed discriminated records,
expected_revision, UUID request_id, structured errors, scoped reads and writes. Native
registry_read/registry_save expose only fixed routes. Generated contracts include registry,
connector diagnostics and mapping provenance. Telemetry labels/timezone derive from the registry.

## 6. Events

ConfigurationChanged v1 includes durable sequence, scope, actor, event ID, revisioned payload
and correlation/causation/idempotency IDs. Same-content replay returns the original result;
conflicting replay is rejected. Entity update and event insertion are one transaction.
Configuration and telemetry outboxes are separate; cloud ACK/upload remains Phase 8 work.

## 7. Tests created and extended

Fourteen registry Python cases cover upgrade preservation, revision/replay conflicts, scope,
references/disable order, six asset-constraint cases, maintenance eligibility, mapping scaling/
provenance, protocol/write rejection, timezone, API persistence, rollback and a new six-asset
hierarchy feeding the adapter. Three frontend cases cover conflict/draft handling, browser
preview and UTC maintenance controls. Native tests now write configuration and confirm restart
persistence. Existing telemetry tests were adapted to registry-backed normalization.

## 12. Known limitations

One scoped organization/facility per edge store; 100 registry records and 150,000 serialized entity
bytes; 10,000 configuration events; one enabled active_power/kW mapping per asset; SIMULATOR only.
No destructive delete, real OT protocol or physical writes. Maintenance scheduling uses explicit
UTC fields; telemetry presentation uses facility timezone. Metadata eligibility is not dispatch
readiness. User RBAC, central provisioning, cloud ACK/retention, store ownership locking, signed
packaging and other metric families remain later work. Phase 2 telemetry capacity still applies.

## 13. Mocks and fixtures

The original five assets and nominal loads are synthetic bootstrap configuration. Existing
history is retained; new records can be added. The adapter generates deterministic seed/tick/
asset power values and has no execute method. UI unit tests mock native IPC; repository, process
and Rust checks use actual SQLite, runtime and HTTP/SSE. No real safety or savings claims.

## 14. Technical debt

JSON documents in the purpose-built SQLite registry rely on domain validation for relationships;
central relational schemas/RLS remain future work. Snapshot reads and bounded single-writer
transactions favor prototype simplicity; large installations require qualification. No durable
user identity is attributed: audit actor explicitly denotes the local simulation session.
Events are preserved until a future acknowledged compaction policy. Installer issues from Phase 2
remain documented; the temporary QA bundle is not a distributable product.

## 15. Security and safety

Scope IDs cannot be reassigned. Server validates references, versions, writable=false and the
SIMULATOR protocol. Critical assets cannot declare flexibility; reduction/load/time/maintenance
constraints are validated. Unsupported scope/protocol/write attempts are tested. Secrets remain
native-owned; browser origins are denied; new IPC cannot access arbitrary URLs, databases or OT.
Configuration metadata never bypasses authorization or creates a physical dispatch path.

## 16. Performance

Registry refresh is approximately every two seconds in the UI; simulator polls configuration
near 1 Hz. Record/body/event limits bound native snapshots and preserve audit data by rejecting
at capacity. No new industrial throughput or long-duration soak claim is made. Phase 2 benchmark
figures are historical and do not certify the expanded registry-backed pipeline.
